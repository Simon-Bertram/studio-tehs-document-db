# Publish a research article

## Goal

Create a long-form website page with slug, township scope, and optional map or article-link modules.

## Steps

1. Open **The Website → Research Articles & Overviews** and create a new document.
2. Set **Page Title** and generate the **URL Slug** (both required).
3. Tick **Show in the public highlight grid** only when this page should appear in the home research teasers. Optional **Highlight order** (1–24) is sort order, not quality.
4. If matching an imported Book or catalog record, set **Archive ID**—it must be unique.
5. Add **Townships** that define the research article’s geographic scope.
6. In **Context**, tag **People Mentioned** and **Organizations** (businesses and organizations) discussed in the article. Create or reuse records under Taxonomies & Entities.
7. In **Page Content & Layout Canvas**, write Portable Text content.
8. Prefer **Historical Image** when the photograph is already in **The Archive → Historical Images**. Press Enter for a new line and use the **+** button, or type `/` and choose **Historical Image**. Search by caption or Archive ID. Leave Caption and Alt Text blank to use the catalog caption, then choose **Image Role**: Primary illustration or Supporting image (defaults to Primary).
9. Use **Uploaded Image** only if the photograph is not in that collection. If it belongs in the archive, [catalog it as a Historical Image](./catalog-historical-image.mdx) first, then insert **Historical Image** from the collection. To upload a non-catalog image, choose **Uploaded Image**, add **Caption** and **Alt Text**, then choose **Image Role**.
10. Drag the block handle to place images between paragraphs.
11. Optionally insert an **Interactive Map Module** with historical map year and engine embed URL.
12. Optionally insert a **Nested Navigation Portal Index** linking to other research articles.
13. In **Notes & References**, add published bibliographic notes, endnotes, and web links that should appear with the article.
14. In **Internal → Internal Comments**, add private working notes (QA, sources to check, unfinished remarks). This field **will not appear on the public site**.
15. Publish when ready.

## Field notes

- Use Research Article for modern research and overviews—not for raw clipping transcriptions and not for Then & Now landmark comparisons ([choose the right type](./choose-document-type.mdx)). For a historical and modern photograph of the same place, see [Publish a Then & Now](./publish-then-and-now.mdx).
- **Show in the public highlight grid** is for editors curating home — leave it off for most articles.
- **People Mentioned** and **Organizations** (businesses and organizations in one field) live under **Context**. Create or reuse the person, business, or organization document first.
- Image vertical order is the block order in the canvas; **Image Role** (`figure` / `aside`) is a semantic hint—Primary vs Supporting—for how the website should present the image, not raw CSS layout.
- Prefer **Historical Image** (a link to **The Archive → Historical Images**) over **Uploaded Image**. Upload only if the photograph is not in that collection; if it belongs in the archive, catalog it there first, then insert it from the collection.
- Map modules need both a target year and an embeddable application URL for the map engine.
- In **Notes & References**, type the citation, select the title, and paste a URL to attach a link. That field is published; do not put private or unfinished notes there.
- **Internal Comments** is Studio-only and never goes on the public site. Use it for working notes that editors should see and the public should not.
