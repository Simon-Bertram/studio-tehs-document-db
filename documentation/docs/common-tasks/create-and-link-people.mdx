# Create and link people

## Goal

Maintain historical person records and reference them from sources, properties, and organisations.

## Steps

1. Open **Taxonomies & Entities → Historical Persons** and create a new document (or find an existing one).
2. Enter first and last name (required). Add prefix/suffix when useful (Capt., Jr., etc.).
3. Optionally set born and died dates (died must be on or after born).
4. Add **Alternate Spellings / Aliases** for variants found in records.
5. Add **Census / Occupation Records** (year + occupation) when known.
6. Optionally tag **Family Lineages** and add **Known Immediate Relatives** (see [Add a family lineage](./add-family-lineage.mdx)).
7. From a primary source, property, or organisation, link the person under People Mentioned, Notable Residents, or Owners.

## Field notes

- Prefer one person document per individual; use aliases instead of duplicate profiles.
- Sources use **People Mentioned**; properties use **Notable Residents / Owners**; organisations use **Owners / Operators**.
- Family grouping and kin links live on the person: **Family Lineages** (broader groups) and **Known Immediate Relatives** (specific relationships).

## Spelling variants

Use **Alternate Spellings / Aliases** for historical variants of the *same* person (e.g. Susanna / Susannah, Ezekial / Ezekiel). Do not create a second person document for a spelling variant.

Do **not** auto-merge different surnames that were historically interchangeable in the region (e.g. Buckwalter / Buchwalder, David / Davies / Davis, John / Jones) unless research shows they are the same individual—those often mark different people or naming patterns across generations.

For a bulk starter list from the Charlestown landowner index (unique names + suggested aliases, no Sanity writes), see the repo folder `migrations/charlestown-people/` (run `bun run migrations/charlestown-people/extract-names.ts`; see that folder’s README for the spelling strategy).
